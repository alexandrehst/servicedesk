09

Do MVP até aposentar o contratado

Time Horizons

A ponte em 7 fases — construir os 20% que cobrem 80% do uso, e provar em paralelo.

Fase 1 · MVP (núcleo MCP) — API + servidor MCP: chamados, fila, status, comentários, e-mail — operar de dentro da IA
Fase 1.5 · UI web — portal do solicitante + fila do agente, sobre a mesma API
Fase 2 — SLA e prazos com alerta de vencimento
Fase 3 — base de conhecimento e respostas prontas
Fase 4 — automações (roteamento por categoria, auto-atribuição)
Fase 5 — catálogo de serviços / self-service
Fase 6 — relatórios e dashboards gerenciais robustos
Fase 7 — integrações (AD/SSO, e-mail bidirecional, Teams/Slack)
Corte — rodar em paralelo ~1 mês → paridade nos 20/80 → aposentar o contratado

Service desk MCP-first

Tool Surface + Estratégia

A nova característica do produto: as funcionalidades centrais viram ferramentas MCP — você (e agentes de IA) operam o sistema por linguagem natural.

toolabrir_chamado(titulo, descricao, categoria, solicitante) → nºescrita
toolbuscar_chamados(status, responsavel, categoria, texto) → listaleitura
toolver_chamado(numero) → detalhe + threadleitura
toolcomentar_chamado(numero, texto, interno?)escrita
toolmudar_status · atribuir_chamado · mudar_prioridadeescrita
toolreabrir / fechar / cancelar_chamado — com confirmaçãoguardrail
toolresumo_fila() → contadores (abertos, por técnico, por categoria)leitura
toolchamados_parecidos(texto) → duplicados na aberturaleitura
rsrcResources: "chamado" e "fila" como leitura barata de contextomcp
prptPrompts: template "triagem de chamado" pronto pra IAmcp
arqAPI-first: MCP e UI web consomem a mesma camada de domínio — zero lógica duplicadapilar
arqGerar o schema das tools da mesma spec da API (evita dessincronia)·
arqAuth com token escopado por identidade; ações atribuídas no log de auditoria·
arqEscrita via IA sempre com human-in-the-loop em ações irreversíveis + rate limit·
usoAbrir/triar por linguagem natural · copiloto do técnico ("o que faço com o #1042?") · resumo do dia·
futAs mesmas tools alimentam bots de Teams/Slack — antecipa a Fase 7·
Síntese · o clímax

A espinha dorsal do MVP

Doze técnicas, cento e cinco ideias — e todas convergem para seis. Se o dia 1 acertar só isto, o sistema já vence o "volta pro WhatsApp".

MUST 1
Abrir chamado
Formulário de 4 campos, <60s, número legível na hora
MUST 2
Fila com dono visível
O que é meu · o que está sem dono · self-assign 1 clique
MUST 3
Status = fonte da verdade
Máx. 5 estados claros; nada mora na cabeça do técnico
MUST 4
Thread de comentários
Conversa rastreável presa ao número do chamado
MUST 5
E-mail nos eventos-chave
Abertura e resolução — só o que importa, nunca ruído
MUST 6
Busca simples
Por status e texto — pra não reabrir o já resolvido
🧲Uma alavanca governa metade das ideias. "Nada cair no esquecimento" (#33), "chamado sem dono some" (#62) e "o que está sem dono" (#41) são a mesma coisa: dono único + status sempre visíveis.
🧩Uma ideia simplifica o sistema inteiro. Fundir categoria + fila em "time responsável" (#56) resolve o schema mínimo (#85) de graça — menos conceitos, menos telas, sem perder roteamento.
🌉O plano de aposentar o contratado já está montado. "Rodar em paralelo ~1 mês" + "paridade nos 20/80" = critério objetivo de corte. Não clone o ServiceNow; cubra os 20% que importam e prove em paralelo.
🤖O MCP dispensa o motor de automações. Expor as funcionalidades como ferramentas MCP faz a IA virar a camada de automação — externa, sem workflow engine interno. Você pode pular a Fase 4. E como o software contratado quase certamente não expõe MCP, isto vira o "porquê construir em vez de comprar". O preço: API-first / camada de domínio limpa sobe para prioridade de dia 1 — é o 7º pilar do MVP.
